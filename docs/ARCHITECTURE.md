# Explorer — архитектура проекта

**Версия:** 0.1 · **Дата:** 2026-10-07, сверено с кодом 2026-10-15
**Движок:** Godot 4.7.2 stable, GDScript, рендерер Compatibility (ПК и веб).
**Дизайн:** [GDD.md](GDD.md) v0.2.

Документ описывает устройство кода: модули, данные, порядок обновления, рендер и тесты. Решения, проверенные по официальной документации Godot, отмечены ссылками в конце.

---

## 1. Принципы

1. **Веб с первой вехи.** Рендерер Compatibility (WebGL2) везде; веб-сборка без потоков. Всё тяжёлое (генерация, мешинг) — порциями по кадрам с бюджетом времени. Потоки на десктопе — возможная оптимизация позже, архитектура от них не зависит.
2. **Чистая логика отдельно от сцены.** Генерация, правила рельефа, кинематика, счёт — классы без доступа к дереву сцены. Их можно тестировать headless.
3. **Детерминизм.** Всё случайное — от `seed` забега и координат. Глобальный `randf()`/`randi()` запрещён.
4. **Data-driven баланс.** Числа живут в `.tres`-ресурсах, а не в коде.
5. **Без god-объектов.** Синглтонов четыре (`EventBus`, `Balance`, `Settings`, `ShaderCache`), и ни один не хранит состояние забега.

**Соглашения:**

- Файлы и папки — `snake_case`; `class_name` и узлы — `PascalCase`; константы — `UPPER_SNAKE`; приватное — с `_`.
- Сигналы — глагол в прошедшем времени: `chunk_loaded`, `cargo_shipped`.
- Один `class_name` на файл; сцена лежит рядом со своим скриптом.
- Всё типизировано: параметры, возвращаемые значения, переменные.
- Идентификаторы — на английском, комментарии и документация — на русском.
- Скрипты `.ps1` сохраняются в UTF-8 с BOM: иначе Windows PowerShell 5.1 читает кириллицу как ANSI.

## 3. Модули

### 3.1 Чистая логика (без сцены, тестируется headless)

| Модуль | Ответственность |
|---|---|
| `Grid` | Константы (`CHUNK = 32`, `APRON = 1`, `TIER_H = 0.5625` — визуальная высота яруса, 9 пикселей мира) и преобразования tile ↔ chunk ↔ world, индексы углов |
| `DetRng` | `hash4(seed, a, b, c) -> int`, `unit(...) -> float` (0…1), `rng_for(...) -> RandomNumberGenerator`, `mix` |
| `ChunkData` | Хранилище одного чанка (§4) |
| `TerrainRules` | Выбор диагонали тайла (`diagonal_02`) и высота в точке тайла (`height_in_tile`); релаксация до Δ ≤ 1 — внутри `Deformation` (`_relax`) |
| `TerrainGenerator` | seed + координаты чанка → `ChunkData`; все решения от мировых координат |
| `DiffStore` | Изменения поверх процедурной базы: записи тайлов (собранные и выпавшие находки и решение по канистрам помнит `PickupField`) |
| `TerrainData` | Реестр загруженных чанков; применение diff при загрузке; запись правок во все чанки-владельцы; dirty-секции |
| `TerrainQuery` | Высота, нормаль, стенка, вода, материал в точке и на ребре |
| `Deformation` | Воронка, борозда, разлом по углам тайлов загруженных чанков: общие вершины двигаются вместе, релаксация до Δ ≤ 1 (опускает высокие или поднимает низкие углы, неподвижные вершины площадок не трогает); у разлома — стенка вдоль линии и пандусы каждые 5–12 тайлов (у сильного толчка реже); вода затапливает опустившееся и уходит с поднятого; запись через `TerrainData.write_tile`. Вал червя возвращается по записям исходных высот; вершина, у которой тайл в выгруженном чанке, откладывается в `TerrainData.pending_restores` и возвращается после загрузки чанка (`restore_pending` из `WorldStreamer`). Релаксация: если обе стороны упёрлись в неподвижные вершины, углы сводятся к ним; остатки с Δ ≥ 2 считает `relax_leftovers` (тесты требуют ноль) |
| `ChunkMesher` | Секция чанка → массивы для `ArrayMesh` (верх, стенки, вода); `UV.x` верха — строка атласа пиксельных текстур (материал, неровный, зыбучий) |
| `TreeField` | Буфер `MultiMesh` деревьев чанка, занятость тайлов |
| `GroundSprites` | Мелочь на земле (M5): пиксельные спрайты травы, кустиков, камней, осколков в `MultiMesh` чанка (цвет и вид — в данных экземпляра); раскладка по хэшу тайла и материалу, высота — из углов тайла, буфер заливается целиком (≈1,4 мс на чанк на ПК); часть сборки `PART_SPRITES`, пересобирается с рельефом тайла (`DIRTY_SPRITES`) |
| `VehicleKinematics` | Один шаг движения по сетке над `VehicleState`: `step` — ввод «относительно мира» (направление на экране → курс), `step_relative` — «относительно машины» (ход −1…1, поворот −1…1; скорость со знаком, задний ход до `REVERSE_FRAC` = 30% Vmax, против хода — сначала тормоз), общий разгон и перемещение — `_drive`; опора — круг `RADIUS` (0,3): по ходу стенку ловит `_move_axis` (удар, скольжение вдоль стенки — и задним ходом), бок и угол корпуса отодвигает `_keep_off_walls` (высокий сосед сбоку, высокий угол соседа по диагонали — `_corner_blocked`); «песочные часы» — `_bridge`: центр пересёк ребро с обрывом ближе `RADIUS` к вершине, едет к ней, угол диагонального тайла в вершине вровень со своим (`_corner_rise`) — центр переносится через вершину на диагональный тайл, без падения; занос (`drift`), машина на подушке считает рёбра по зеркалу воды (`TerrainQuery.edge_rise_float_at`); зыбучий грунт — вязкий разгон и прилипание после стоянки (`mire_grip`, `VehicleState.mire_stuck`); предел скорости сверху `speed_cap` (пустой бак — ползком), круглые препятствия `obstacles` (корпуса севших челноков); порог валки деревьев `fells` и потеря скорости после неё `after_felling` — общие с тараном фауны (`FaunaDirector`) |
| `TerrainConnectivity` | Проверка «ям без выхода»: из каких тайлов окна можно доехать до его границы по рёбрам без подъёма (`trapped_count` — для тестов и `TerrainRepair`) |
| `RunState` | HP, топливо, груз с вытеснением дешёвого, формулы счёта (сдача, аварийный вызов с заказом топлива и запчастей, бонус), итог забега |
| `Leaderboard` | `user://leaderboard.json`, топ-10 по классу, имя — до `NAME_MAX` (8) знаков (длиннее — обрезается при чтении); при чтении записи проверяются (без счёта — отбрасываются), испорченный файл копируется в `leaderboard.json.bad`; запись — во `.tmp` и переименованием поверх (не вышло — прямо в файл) |
| `PickupGenerator` | Находки чанка по правилам GDD §6: один `RandomNumberGenerator` на чанк, бросок на каждый тайл в фиксированном порядке (~0,2 мс на чанк); ремкомплект — на чанк |
| `ShuttleScheduler` | Расписание основного челнока: интервалы и дистанции посадок, анонс площадки за 30 с, окно 20 с с удержанием, пока открыто меню, вылет сразу после сдачи (`depart`); выбор площадки по дистанции |
| `EmergencyCall` | Аварийный челнок: заказ (топливо и запчасти), таймер прилёта, ожидание в небе, пока нет места; выбор тайла посадки (ровный, сухой, без стенок, в 2–4,5 тайла от машины); заказ по умолчанию по нужде |
| `NoiseField` | Шум машины (по скорости) и шумных событий (посадки челноков) — кто кого слышит |
| `FlowField` | Поиск пути фауны: поле расстояний (обход в ширину) до тайла машины в окне 61×61 по рёбрам, проходимым для вида (`passable` одно на оба вида: без уступа вверх и вниз и только суша); строится задачей JobScheduler, одно поле на всех зверей вида |

### 3.2 Узлы сцены

| Узел | Ответственность |
|---|---|
| `JobScheduler` | Очередь задач с приоритетом и бюджетом микросекунд на кадр |
| `WorldStreamer` | Какие чанки нужны, гистерезис загрузки и выгрузки, пул `ChunkNode`; `ready_fraction` — доля собранных чанков вокруг точки (для полосы загрузки; пока ямы не залиты — не больше 0,95), `ready_around` — мир вокруг точки собран и ямы залиты. При обычном старте и после «Заново» мир вокруг точки старта грузится задачами под экраном загрузки (бюджет 30 мс — кадров под экраном не видно). Синхронно (`preload_around`) — только отладочные запуски без трюма |
| `ChunkNode` | 4 × `MeshInstance3D` (секции) + вода + `MultiMeshInstance3D` деревьев и мелочи на земле |
| `Vehicle` | Владеет `VehicleState`, вызывает кинематику (`step` или `step_relative` — по `Settings.control_mode`; автопилот — всегда первый), шлёт события; наклон модели — по четырём точкам опоры, точка за стенкой или обрывом (перепад больше `TILT_STEP` = ¾ яруса) берёт высоту центра (`_support`); `set_class()` меняет модель, тон двигателя и колеи (`VehicleTrail`). `respawn()` — возрождение в песочнице автопилота: модель пересобирается, машина цела и управляема. `sink_on_water()` — гибель над водой: корпус идёт ко дну, как тонущий (`VehicleKinematics.sink_wreck` — без новой гибели). Разряд по машине рисует `ShockFx`: ломаные дуги лентами к камере (`ImmediateMesh`) и белое мерцание корпуса через `material_overlay` — материалы с ключами, которые уже прогреты |
| `MeshKit` | Low-poly геометрия с плоскими гранями: призмы по контуру, правильные многоугольники, треугольники с правильной лицевой стороной — для техники и фауны; `face_mapped` — разметка граней для узора обшивки (UV — точка относительно центра грани, UV2 — её полуразмеры, `COLOR`, `CUSTOM0` и `CUSTOM1` — до двух деталей грани) |
| `PixelFx` | Пиксельные частицы: квад-билборд стороной в целое число пикселей мира (`Grid.ART_PX`), от 3 пикселей — спрайт круга из этих пикселей (`puff`), прозрачность отсечением (`ALPHA_SCISSOR`) — частица гаснет разом. Все `CPUParticles3D` эффектов строят меш через него. Пыль и комья — одни на всех эффектах: `dust` (облачко 4×4, оседает, тормозится воздухом), `clods` (квадрат 2×2, падает по дуге), цвет — `dust_color` / `clod_color` от грунта под эффектом (цветом частиц, материал с цветом вершин); вызывающий задаёт только силу, направление и форму испускания |
| `BodyMaterial` | Материалы техники и фауны с пиксельным узором (M5): `body.gdshader` (фауна), `body_xray.gdshader` (машины — пишет 1 в stencil; силуэт сквозь препятствия — следующий проход `xray_pass`, как `STENCIL_MODE_XRAY`) и `body_faces.gdshader` (челноки и капсула десанта — обшивка по граням без stencil, силуэт машины сквозь них виден), общий код — `body.gdshaderinc`: цвет детали × яркость узора по координатам меша (траки, юбка, щитки, шкура, кольца, чешуя, ил, галька, хитин — по сетке грани); `tinted` — цвет ещё и в вершинах меша (uniform `vertex_tint`, sRGB → линейный, как `vertex_color_is_srgb`; у скакунов хитин, кромка и кость — один материал), `specular` — как `metallic_specular` у `StandardMaterial3D`; uniform-ы, а не `#define`, — вариант шейдера не новый; обшивка техники — по граням: `map_faces` размечает меши `MeshKit.face_mapped`, грань делится на целое число пикселей, детали `Detail` (дверь, люк, решётка; до двух на грань, из мета `details` узла) — прямоугольники на своих гранях; свет — как у `StandardMaterial3D`. Цвет — параметр шейдера: `set_color` / `color_of` (годятся и для `StandardMaterial3D`) |
| `TerrainMaterials` | Общие материалы и меши рельефа: создаются один раз и делятся между всеми чанками (атласы M5, §10) |
| `VehicleModels` | Модели трёх классов из примитивов по `design_references/`: коробки, цилиндры, трубы `_rod` (бампер, кенгурятник), призмы `MeshKit.prism` по контуру (нос ховера, гусеницы танка); материалы для силуэта (stencil; окрашенные части и гусеницы — `BodyMaterial` с узором), вращающиеся части, огонёк антенны `beacon` (`Vehicle` мигает им, пока летит аварийный челнок). Ходовая — в `root`, корпус — в подрессоренном `body`, антенна — на шарнире `antenna`. `build_plain` — без stencil, для экранов вне игры |
| `VehicleRide` | Анимация хода, только модель: тряска `body` (сумма синусов; по скорости, грунту `FLAG_ROUGH`/`FLAG_MIRE` и массе класса), осадка в зыбучем, наклоны от ускорения, колыхание и крен ховера, антенна-хлыст на пружине (инерция, отставание от раскачки `Vehicle.rock`), болтанка ховера в ядре водоворота (`VehicleState.churn` — та же тряска, медленнее) |
| `VehicleTrail` | Следы, пыль и вода от езды. Пыль и комья — `PixelFx.dust` / `clods` (как у всех эффектов). По воде (вброд или на подушке) — как у Нессы, только меньше: V-волна пены (`foam_strip`, два пикселя шириной, плечи до `WAKE_LEN` 1,6 тайла; сила — от скорости в воде; от носа по ходу, задним ходом — от кормы), брызги (`clods` цвета пены); тонет — пузыри. Колея: колея колёс ровера и гусениц танка — отпечатки-квады в одном `MultiMesh` (кольцом по 900), шейдер `track_mark` затемняет ими землю умножением в пикселях сетки рельефа (1/16 тайла: тексель берётся по своему центру, края и рисунок траков — ступеньками; рисунок у колёс и гусениц один), гаснет за 16 с и дальше 13 тайлов от машины, ступенями; пыль (облачка 4×4 текселя) и комья (квадрат 2×2) — `CPUParticles3D` цвета грунта. Сила по материалу: песок, грунт, камень и кристалл — едва; зыбун — колея и грязь без пыли; вода — ничего. Ховер колеи не оставляет — пыль кольцом вокруг юбки |
| `VehicleInput` | Действия ввода: `world_direction` — вектор направления относительно экрана; `drive_turn` — (поворот, ход) для режима «относительно машины» (`Settings.control_mode`; выбирает `Vehicle`) |

| `WorldMap`, `MapMemory` | Карта мира по M (`map`; GDD §8): `CanvasLayer` 5 — над непогодой (4), под HUD (6); игра не на паузе, радар спрятан. `MapMemory` пишет весь забег: по `chunk_built` — цвет чанка 32×32 RGB, пиксель на тайл (`MapRender.tile_color` — общий с отладочной картой, плюс лес; площадок, в отличие от отладочной, нет), порциями по строкам в бюджете 1 мс за кадр; туман войны — уровень тайла (0 — темно, `SCANNED` — был в дальности радара, `SEEN` — видели: `ThreatDirector.visibility` — ясно `SEEN_R` 12, в массе тумана или пыли до её просвета `WeatherFront.clear_radius` по плотности, под грозой до `storm_visibility` 7 по `StormFront.coverage`) и отдельная картинка тумана поверх цвета (цвет фона с непрозрачностью `FOG_A` уровня); отметка — круг вокруг тайла машины, повторно только серп, которого не было в прошлом круге того же уровня, туман закрашивается отрезками строк (`fill_rect`) — дальность радара велика. `WorldMap` рисует видимые чанки (только где есть туман — радар доставал): цвет и туман текстурами (nearest) через `draw_set_transform_matrix`: оси — целые векторы (±2, ±1) по четверти поворота камеры, поэтому тайл — одинаковый ромб 4×2 пикселя; находки `PickupField.known()` — те, что машина видела (`within` в радиусе видимости; ключи копятся весь забег, собранные выпадают сами); площадка челнока — рамкой или стрелкой у края |
| `DevTools` | Параметры запуска, бенчмарк (FPS, p95/p99 и максимум кадра, кадры дольше 33 и 50 мс — `frame_stats`), снимки, сценарии без рук (`--idle`, `--press`; часы — от конца загрузки); `mark(name)` — метка этапа в консоль и `performance.mark` в браузере (её видит раннер `web_bench.mjs`); `--hunt` — автопилот таранит ближайшего зверя (`Autopilot.prey`: с места — прямо на него, на ходу — по дуге не круче 20° от курса, чтобы не терять скорость) |

Звуки — по именам (`Sfx.named`), синтез один раз за сессию (кэш переживает «Заново»). Генераторы — сопрограммы над `Sfx.Synth`: фоновая очередь (`Sfx.prepare`/`Sfx.pump`, качает `AudioDirector`) синтезирует порциями (256 сэмплов генератора, у тяжёлых — 32; шов петли, пик и запись в 16 бит — по 2048) не дольше `synth_budget_usec` за кадр (3 мс, под экраном загрузки — 20 мс; все сразу — почти секунда чёрного экрана в браузере), `Sfx.pending()` — сколько осталось (экран загрузки ждёт всех); щелчок тумблера и люк трюма — первыми; нужный раньше досинтезируется сразу. Гул смерча и водоворота — с первого шага угрозы (образцы прогрева молчат). Червь под песком гудит ровной петлёй `ground_hum` (свой плеер, громкость по расстоянию, тише гула землетрясения). Петля двигателя — одна на сессию (`Sfx.cached`); двигатель — `EngineSound` (зацикленный WAV, тон и громкость от скорости и газа) |
| `Hud` | Отображение; подписан на `EventBus`, логики не содержит. Слева вверху — КОРПУС, ТОПЛИВО, ГРУЗ; урон корпусу и ремонт — числом у машины (`float_number`: «-15» / «+20», над машиной по `camera.unproject_position`, всплывает и гаснет). Внутри — `Radar` и `Pager` (угрозы и «МАЛО ТОПЛИВА»: только название), вспышка экрана от молнии; внизу — таймеры челноков и при пустом баке мигающие «НЕТ ТОПЛИВА» / вызов аварийного |

### 3.3 Autoload-синглтоны

`PixelFx`, `BodyMaterial`, `MeshKit` и прочие помощники — статические классы (`class_name`), не автозагрузки (§3.2).

| Синглтон | Зачем |
|---|---|
| `EventBus` | Только сигналы, без состояния. Связи «один ко многим» (HUD, пейджер, аудио, тряска камеры) без ссылок между модулями |
| `Balance` | Загружает `data/*.tres`, отдаёт типизированный доступ: `Balance.vehicle(&"rover")`, `Balance.rules`. В тестах подменяется |
| `Settings` | Пользовательские настройки (тряска, громкость, режим управления `control_mode` и «вид сзади» `chase_camera`, `chase()`), `user://settings.cfg`; при чтении значения проверяются по типу, громкость зажимается в 0…1 (испорченное значение — по умолчанию); громкость применяется к шине Master по квадрату уровня (`apply_volume`), на нуле шина выключена |
| `ShaderCache` | Держит материалы образцов прогрева всю сессию: шейдер `StandardMaterial3D` общий на набор свойств, и Godot выбрасывает его (с программами GPU) вместе с последним материалом — без удержания каждая молния и новый червь компилировали шейдеры заново. Держит и материалы трюма (`HangarScreen` после прогрева света). Переживает «Заново» |

**Правила шины:** по `EventBus` идут только уведомления. Тесные связи (машина ↔ рельеф) — прямые типизированные ссылки. Запросы с ответом через шину запрещены.

`RunState` — не синглтон: им владеет `GameFlow`, экран итога — дочерняя сцена, смены сцен нет. `JobScheduler` — узел под миром.

## 4. Данные рельефа

### 4.1 ChunkData

Чанк хранит **окно 34×34 тайла**: свои 32×32 плюс по одному ряду тайлов соседей (фартук). Фартук детерминированно совпадает с данными соседа, поэтому мешер рисует стенки на границе без доступа к соседним чанкам.

```gdscript
class_name ChunkData extends RefCounted
const N := 34                       # 32 + 2 × фартук
var coord: Vector2i
var corners: PackedByteArray        # N*N*4: ярус + 64; угол 0=NW(-x,-z) 1=NE 2=SE 3=SW
var material: PackedByteArray       # N*N: 0 грунт, 1 песок, 2 камень, 3 кристалл
var water_level: PackedByteArray    # N*N: 0 — нет воды, иначе ярус зеркала + 64
var trees: PackedByteArray          # N*N: 0 — нет; биты 0–5 тип + 1, бит 6 повален (TREE_FELLED)
var tree_offset: PackedByteArray    # N*N: 4 бита x | 4 бита z (доли тайла)
var flags: PackedByteArray          # N*N: бит 0 площадка (не деформируется), 1 гнездо, 2 обломки, 3 неровный, 4 зыбучий
var biome: PackedByteArray          # N*N: Biome
var dirty_sections: int             # биты 0–3 секции 16×16, 4 вода, 5 деревья, 6 мелочь на земле
```

Размер — около 12 КБ на чанк; в памяти 25–49 чанков.

### 4.2 Диффы

- `DiffStore`: словарь «ключ тайла → полная запись тайла» (4 угла, материал, вода, дерево, флаги — 8 байт). Ключ — упакованные мировые координаты: `(wx + 2^20) << 21 | (wz + 2^20)`.
- Ключ — тайл, а не угол: при стенке у вершины несколько высот, запись тайла однозначна.
- Операция над углом задаётся в мировых координатах вершины и разворачивается на тайлы вокруг неё. `TerrainData.write_tile()` пишет запись во внутреннюю область чанка-владельца и в фартуки до трёх соседних загруженных чанков, помечая их dirty.
- Собранные и выпавшие находки помнит `PickupField` (`_taken`, `_dropped`), не `DiffStore`.
- Плотность канистр (зависит от времени, GDD §7.2) решается при **первой** загрузке чанка; решение запоминает `PickupField` (`_canisters`), чтобы повторная загрузка дала то же самое.

### 4.3 Бесшовная генерация

- **Высота вершины** — чистая функция `f(x, z)` от мировых координат (ярусы), затем округление. Состав:
  - база — крупный шум с большой амплитудой и детальный шум;
  - горы — маска плюс широкие гребни;
  - одна ступенчатая функция по сумме «база + горы»: ширина подъёма между полками зависит от **скалистости** (горы, ущелья, выходы скал) — на скалах резко (обрывы), на грунте полого; в зонах пандусов и проездах ступеней нет;
  - **дюны** (GDD §3.4) — поверх ступеней, до ущелий: маска поля × профиль гряд × гашение к площадкам (ниже);
  - ущелья — полоса вдоль изолинии шума с domain warp, вырезается вниз;
  - **дамбы** между водными областями с разными уровнями;
  - площадки челнока (выравнивание 5×5 и пологое кольцо) и чаши луж.
- **Дюнные поля:** маска `dune_field(x, z)` 0..1 — произведение плавных множителей: середина пустыни (шум кратеров выше порога биома на `dune_core_from…dune_core_to`), шум выбора поля (частота 1/300, порог 0 — дюны получают ~60 % крупных пустынь), вдали от гор, выходов скал, ущелий, леса и воды (база выше самой высокой воды областей на 1,5–4 яруса). Сначала считается дешёвая часть (кратеры × выбор, `_dune_gate`) — почти везде дальше дело не идёт. В поле ступени сглажены (`gentle ≥ маски`), сверху — профиль гряд `_dune_relief`: координата вдоль ветра (одно случайное направление на забег, по seed) плюс изгиб шумом → пила с шагом `dune_spacing` (10 тайлов), пологий наветренный склон и более крутой подветренный (`dune_lee`), высота гребня `dune_height` × шум вдоль гребня (0,4–1) — после округления гребни в 1–2 яруса, низкие гряды рвутся на отрезки. Высота гряд гаснет к площадкам челнока (0 в их пологом кольце, полная — через `dune_pad_fade` за ним): площадки выбираются по высоте без гряд (`_height(…, dunes = false, …)`), поэтому от дюн не зависят и рекурсии нет; место в дюнах площадка получает со штрафом (`dune_pad_penalty`). В горячем пути гашение считается по списку площадок задачи, иначе — по кэшу блоков (результат одинаков; подготовка задачи берёт блоки с запасом `pad_blend + dune_pad_fade`). Лужи в поле не ставятся.
- **Седловины:** вершины считаются на окне с запасом в одну вершину (`EXT = 37`). Вершина — нижний угол седловидного тайла — поднимается на ярус, если ни один из её четырёх тайлов не станет круче яруса. Решение зависит только от вершин на расстоянии 1, поэтому одинаково во всех окнах.
- **Крутизна гряд:** склон гряды вместе с краем маски и уклоном базы местами даёт тайл с разбросом 2 (он уплощился бы в стенку). Вершина с грядами (`GenJob.ext_dune = 2`), не тронутая правкой седловин, сдвигается на ±1 ярус, если так все четыре её тайла укладываются в ярус и ни один не становится седловиной, — тоже по вершинам на расстоянии 1. Замер по 7 seed: на ~100 тыс. тайлов поля две стенки (самый край поля у готового обрыва, гряды там — доли яруса, а сдвигать пришлось бы две вершины сразу) против ~40 уступов и обрывов там же без дюн.
- **Тайл** берёт углы из вершин. Разброс ≥ 2 — тайл уплощается до минимума (стенки на высоких рёбрах). Разброс 1 иногда тоже уплощается — уступ, вероятность растёт со скалистостью; на дюнах уступов нет. Тайл дюнного поля (все четыре угла в маске) — песок биома «Кратерные поля» без россыпей (кристаллы занесены). «Кресты» на рёбрах при таком построении невозможны.
- **Вода:** уровень тайла — уровень его водной области (искривлённая решётка 192 тайла, уровень по хэшу области, ±1); в луже — уровень полки, если он выше. Дамбы гарантируют, что вода разных уровней не соприкасается; тест `test_no_hanging_water_and_few_saddles` проверяет, что вода нигде не висит над сухим соседом.
- **Лужи:** ячейки 22 тайла; место — ровная полка (36 проб высоты в трёх кольцах на одном ярусе), выше воды области, не на скалах, не в дюнном поле и не на площадке челнока (ровная площадка проходила проверку полки — около 1 % площадок получали чашу).
- **Швов нет по построению:** окно чанка — это те же функции на тех же мировых координатах.
- **Против ям без выхода:** проезды (решётка коридоров с шагом 56, где всё пологое), обрывы только на выпуклостях, остаток — `TerrainRepair` (§4.4).
- **Этапы задачи генерации:** подготовка (сначала площадки всех блоков, которые могут задеть гнёзда и лужи, — по одной за шаг, это десятки проб высоты; затем гнёзда и лужи — они только читают кэш площадок), вершины с запасом (и признак дюн вершины), правка седловин и крутизны гряд, тайлы. Каждый этап режется по рядам под бюджет кадра. Дюны добавляют ~2–3 % к среднему чанку и ~10 % к чанку посреди поля.

```gdscript
class_name TerrainGenerator extends RefCounted
func generate(coord: Vector2i) -> ChunkData                 # полный проход (тесты, предпросмотр)
func begin(coord: Vector2i) -> GenJob
func step(job: GenJob, deadline_usec: int) -> bool
func height_at(x: float, z: float) -> float                 # f(x, z) с площадками и лужами
func water_tier(tx: int, tz: int) -> int                    # уровень области или лужи
func pad_of_block(block: Vector2i) -> Vector3i              # (x, z, ярус) или z = NO_PAD
func puddle_of_cell(cell: Vector2i) -> Vector4              # (x, z, радиус, ярус) или NO_PUDDLE
func dune_field(x: float, z: float) -> float                # маска дюнного поля 0..1 (без площадок)
func dune_height(x: float, z: float) -> float               # сколько ярусов добавляют гряды
func dune_tile(tx: int, tz: int) -> bool                    # тайл в поле (все углы в маске)
```

`TerrainParams.dunes_enabled = false` (параметр запуска `--no-dunes`) — тот же мир без дюнных полей: сравнить место «до/после».

Генерация — ~30 мс на чанк на ПК; подобрать параметры помогает `src/debug/map_preview.gd` (PNG-карта, §12), проверки качества — `TerrainChecks` (седловины, висящая вода).

### 4.4 Заливка ям и деформации

- **Заливка ям** (`TerrainRepair`). После загрузки чанка — окрестность новых чанков ±2 чанка (в пределах прямоугольника круга загрузки; ямы без выхода у генератора — до ~60 тайлов в поперечнике), после разлома — весь прямоугольник круга загрузки. Область обходится в обратную сторону: от выходов (граница окна и тайлы рядом с незагруженными чанками) по рёбрам без подъёма. Каждая недостижимая компонента поднимается до уровня самого низкого края; компонента обходится и поднимается порциями (курсор между шагами). Тайлы вне ямы не меняются, поэтому новых ям не появляется. Правки идут через `TerrainData.write_tile` — во все окна чанков и в `DiffStore`.
- `WorldStreamer` запускает `PitFillJob` порциями после того, как генерация вокруг закончилась. До 4 проходов, пока есть изменения; изменённые секции пересобираются.
- По тестам на трёх seed'ах в окне 160×160 заливается меньше 2% тайлов; после заливки запертых тайлов нет.

- Воронка, борозда, валы: `Deformation.crater` / `furrow` / `raise_vertices` и релаксация `_relax` до Δ ≤ 1 внутри каждого тайла — стенок не появляется.
- Разлом — единственная операция, создающая стенки. Пандусы — каждые 5–12 тайлов вдоль линии (у сильного толчка реже); после него — заливка ям во всём круге загрузки (`request_pit_fill`).
- Тайлы с флагом площадки не меняются; соседи релаксируют к их краю.
- `Deformation` возвращает список изменённых ключей тайлов → `TerrainData` → dirty-секции → `JobScheduler` пересобирает только их.

## 5. Меш, деревья, стриминг

### 5.1 ChunkMesher

- Прямые packed-массивы (`PackedVector3Array`, `PackedColorArray`, `PackedInt32Array`), предвыделенные через `resize()` и заполняемые по индексу, → `ArrayMesh.add_surface_from_arrays()`. Это быстрее `SurfaceTool` в GDScript: нет вызова на каждую вершину.
- Освещение плоское: нормаль грани считает фрагментный шейдер через `dFdx`/`dFdy`. Вершинные нормали в меше всё же есть (наклон тайла; у стенки — наружу): из них берётся смещение теней по нормали, без них грани затеняют сами себя («штриховка»). Верх — 4 вершины и 6 индексов на тайл, стенка — 4 вершины на ребро; признак стенки — в `COLOR.a`.
- Стенку рисует только более высокая сторона ребра — без дублей и без зависимости от соседнего чанка (данные фартука).
- 4 секции 16×16 на чанк; деформация пересобирает только затронутые секции.
- Сборка секции — ~0,5–0,8 мс на ПК (прямой доступ к байтам углов, оттенок тайла — дешёвый хэш координат), поэтому секция строится целиком за один шаг задачи; `BuildChunkJob` проверяет дедлайн между секциями.
- Вода — отдельный меш чанка: квады на уровне воды там, где он выше самого низкого угла тайла.

### 5.2 Деревья

`TreeField.build()` заполняет `MultiMesh` чанка через `set_instance_transform/color`: стволы, кроны двух типов (отдельные `MultiMesh`), поваленные стволы. На чанк — до сотни экземпляров, ~0,5 мс. Если понадобится быстрее — запись `MultiMesh.buffer` целиком. В Compatibility цвет и custom data экземпляра хранятся в half-float — идентификаторы туда не пакуем, типы деревьев — отдельные `MultiMesh`.

### 5.3 WorldStreamer и JobScheduler

- Кадр 480×320 при тайле 40 пикселей в ширину: ~12 ромбов по ширине (при 32 было ~15), на земле — след примерно 21×28 мировых единиц, повёрнутый на 45° → полудиагональ ≈ 18 тайлов.
- Радиус загрузки `R_load = 17 + 32 = 49` тайлов (чанк грузится, если его AABB пересекает круг) → сетка 5×5 чанков. Выгрузка — при `R_load + 32` (гистерезис).
- Центр круга — позиция машины + скорость × 2 с. Приоритет задачи — расстояние до центра.
- Пул `ChunkNode`: узлы и меши переиспользуются (`clear_surfaces()` + новая поверхность); у `ChunkNode` интерполяция физики выключена (`PHYSICS_INTERPOLATION_MODE_OFF`) — сброс при переносе не нужен.
- Худший случай — ховер (7,5 тайл/с) по диагонали: новый ряд из 5 чанков каждые ~4 с; укладывается при 6 мс на кадр.
- Под экраном загрузки бюджет поднят до 30 мс (`GameFlow.LOADING_JOB_BUDGET_USEC`): кадров не видно, мир собирается быстрее; когда мир вокруг старта готов — обычный бюджет.

- Внешние силы (ветер бури, тяга смерча) источник кладёт в `state.ext_accel` (уже делённую на массу); кинематика копит их в сносе `push_vel`, который затухает сам (`PUSH_DAMP = 2`, при силе a снос выходит на a/2) и гасится стенками.
- Разгон с места может быть сильнее обычного (`launch_accel`, у танка 6): к 60% Vmax сходит к `accel`.
- Тормоза нет: без ввода машина замедляется с `brake_decel`. Целевая скорость — `max_speed × газ × max(cos(угол до нужного курса), 0)`; с места (скорость < 1) при угле больше 12° она 0 — машина доворачивает на месте и потом разгоняется. Танк (`turn_in_place`) стоит при угле больше 45° и на ходу.
- Сдвиг за шаг делится на под-шаги по пересечению рёбер тайлов.
- Перепад берётся в точке пересечения ребра (`edge_rise_at`, линейно между углами). Больше 1/3 яруса вверх — стенка: составляющая скорости поперёк ребра обнуляется, курс выравнивается вдоль стенки (скольжение). Больше 1/3 яруса вниз — падение.
- Падение: машина остаётся в пределах соседнего нижнего тайла, горизонтальная скорость ×0,5, приземление по высоте поверхности, урон `fall_damage`.
- Стенка проверяется передним краем машины (центр ± 0,3 тайла), падение — центром.
- Вода глубже допустимой для класса — не стенка: заехать или упасть можно, но машина переходит в состояние «тонет» (`drowning`): управления нет, скорость гаснет, машина опускается на дно и через `DROWN_TIME` (2 с) гибнет — `StepResult.drowned`, `EventBus.vehicle_died(&"drowned")`. Удар о воду урона не наносит. Ховер не тонет.
- Отладка: `--spawn=X,Z` — старт в точке мира, `--course=D` — автопилот едет строго по курсу.
- Наклон корпуса — из 4 точек опоры (`Vehicle._support` → `query.surface_y` вокруг позиции), только для визуала.

## 9. Порядок обновления

**`_physics_process`, 60 Гц.** Мир вызывает подсистемы явно, в фиксированном порядке — ради детерминизма.
Сейчас: `GameFlow._step` (родитель, идёт первым) — фокус стримера (`update_focus`), `vis_center`, а в фазе вылазки
`RunState.tick`, подбор находок, расход топлива, `ShuttleController.step`, `ThreatDirector.step`, `FaunaDirector.step`;
затем `Vehicle` — шаг кинематики и сигналы урона и гибели. Целевой порядок:

1. Ввод: `VehicleInput.world_direction(camera)` или `drive_turn()`.
2. Погода и угрозы: таймеры, телеграфы, внешние силы → `state.ext_accel`.
3. Фауна.
4. `VehicleKinematics.step` → события урона, падений, деревьев.
5. Находки, зона челнока, аварийный челнок.
6. Очередь деформаций → `TerrainData` → dirty-секции (меши здесь не трогаем).
7. `RunState.tick(dt)`: топливо, таймеры челнока, проверка HP = 0; пустой бак — машина ползёт (`Vehicle.out_of_fuel`).
8. `WorldStreamer.update_focus(pos, vel)` (упреждение по скорости — внутри) — только обновляет очередь.

**`_process`:**

- `JobScheduler` выполняет задачи (генерация, мешинг секций, деревья) в пределах бюджета.
- `IsoCameraRig` следует за `vehicle.get_global_transform_interpolated().origin` + упреждение и привязывает позицию к пиксельной сетке рендера в плоскости экрана. У камеры `physics_interpolation_mode = OFF`.
- Глобальные uniform погоды ставят `GameFlow` (`vis_center`, каждый физический шаг), `WeatherFront` (`weather_*`, `vis_color`) и `StormFront` (`storm_*`).
- HUD обновляется только по сигналам.

## 10. Рендер в Compatibility

- **Единый пиксель мира `Grid.ART_PX` = 1/16 тайла** (тексель рельефа; в шейдерах — `ART_PX` из `visibility.gdshaderinc`): узоры моделей (`px` в `BodyMaterial` с поправкой на масштаб узла, у деревьев — на масштаб экземпляра, у находок — в долях `size`), частицы (`PixelFx`), ширины молний и дуг. Плоские эффекты на земле (водоворот, знак посадки, пена, колея, рябь зыбучего грунта, круги за илозубом) берут каждый пиксель по центру пикселя мира (обратная матрица экземпляра — из `vertex()`: в `fragment()` у MultiMesh `MODEL_MATRIX` — без экземпляра); ширины плоских мешей-эффектов (трещины червя и землетрясения, пунктир зоны погрузки, кольцо и перекрестье капсулы, V-след Нессы, дуги разряда по машине) — целые пиксели мира, прозрачность и цвет меняются ступенями. Плавные поля (туман и пыль `fog_layer`, пелена `vis_hidden`/`weather_color`, тень туч `storm_shade`) — `art_snap` + `art_steps` (ступени без дизеринга: слои в шахматку складываются в мелкую сетку). Тени — `directional_shadow/size = 1024`, `soft_shadow_filter_quality = 0`, `shadow_blur = 0`, смещения 0,04 / 0,8 (меньше — полосы на земле, больше — тень отрывается).
- **Пиксель-арт без шейдеров постобработки:** базовое разрешение 480×320 (`display/window/size/viewport_*`), окно 960×640, `stretch/mode = viewport`, `stretch/aspect = keep` (3:2 с полями), `stretch/scale_mode = integer`, фильтр холста `nearest`, MSAA выключен. Шрифт — пиксельный Ark Pixel 10 px (`assets/fonts/ark-pixel-10px.ttf`, OFL; урезан `pyftsubset` до латиницы, кириллицы и знаков): тема проекта `assets/fonts/ui_theme.tres`, импорт без сглаживания, хинтинга и дробных позиций; кегли только 10 и 20 (`UiKit.TEXT`, `UiKit.TITLE`). Знака минус U+2212 в шрифте нет — в тексте на экране дефис. Камера: наклон 50° (при 45° грань тайла с поднятым углом, отвёрнутая от камеры, почти параллельна взгляду и сжималась в линию в пиксель), `size = 320 × √2 / 40`, чтобы ромб тайла был 40 пикселей в ширину (≈ 31 в высоту); отладочный `--zoom=N`.
- **Тени:** одна ортогональная карта (`SHADOW_ORTHOGONAL`) на 40 единиц, `shadow_bias = 0.04`, `shadow_normal_bias = 0.8`; параметр запуска `--no-shadows` выключает их.

- **Террейн** (`terrain.gdshader`): `COLOR.rgb` — тинт материала, `COLOR.a` — признак стенки. Во `fragment()`: `NORMAL = normalize(cross(dFdx(VERTEX), dFdy(VERTEX)))` с разворотом к камере — flat-освещение. Верх тайла — тёмная кромка (сетка ромбов): ряд текселей №0 по x и по z, на каждой границе тайлов — линия ровно в пиксель мира. Рябь зыбучего грунта — в центрах текселей, время ступенями (6 раз в секунду). Стенки — страты по ярусу (`floor(world_y / tier_h)`, `Grid.TIER_H` = 0,5625), три цвета по кругу.
- **Пиксельные текстуры верха (M5):** атлас `assets/textures/terrain_tops.png` (6 строк по 64×64 текселя; клетка накрывает 4×4 тайла и бесшовна — периодический шум и ячейки Вороного, берётся по мировым XZ) генерирует `tools/textures/gen_terrain_tops.gd` (`godot --headless --path . --script res://tools/textures/gen_terrain_tops.gd`), его можно и перерисовать вручную. Текстура в оттенках серого: шейдер умножает цвет материала на значение × 1,5 — палитра и погода прежние. Импорт — без сжатия и мипмапов (`compress/mode=0`, `detect_3d/compress_to=0`), сэмплер — `filter_nearest`. Стенки обрывов — атлас `assets/textures/cliff_walls.png` (4 варианта по 16×10 текселей на тайл × ярус, `tools/textures/gen_cliff_walls.gd`): горизонталь — мировая координата вдоль стенки (ось выбирается по нормали грани), вертикаль — доля яруса, вариант — по хэшу места и яруса; множит цвет пласта по абсолютному ярусу. Вода — перебор палитры: `assets/textures/water_cycle.png` (16×16 на тайл, бесшовная, `tools/textures/gen_water_cycle.gd`) хранит фазу волны 0…7, `water.gdshader` сдвигает её со временем (4 шага в секунду) и берёт оттенок из палитры в 8 шагов; цвет по глубине — 4 ступени. Мелочь на земле — `assets/textures/ground_sprites.png` (8 спрайтов 8×8, `tools/textures/gen_ground_sprites.gd`, рисунки символами прямо в генераторе), `ground_sprite.gdshader`: билборд лицом в камеру, низом на земле (пиксель спрайта квадратный, как у частиц), основание привязано к пиксельной сетке экрана, отсечение по альфе, свет как у земли, без теней.
- **Видимость** (`visibility.gdshaderinc`): пелена — только внутри массы непогоды (`weather_center`, `weather_radius`), у машины (`vis_center`) просвет `weather_clear`, дальше цвет `vis_color` густеет до `weather_max` (`vis_hidden`, `weather_color`); отдельного радиуса видимости нет. Глобальные uniform объявлены в `[shader_globals]` проекта и выставляются через `RenderingServer.global_shader_parameter_set()`.
- **Деревья** — `MultiMeshInstance3D` на чанк, `use_colors = true`.
- **Вода** — прозрачный меш чанка (`blend_mix`), цвет по глубине через vertex color, без чтения depth texture.
- **Силуэт за стеной** — шейдер `body_xray.gdshader` пишет 1 в stencil, следующий проход `BodyMaterial.xray_pass` — `StandardMaterial3D` с `STENCIL_MODE_CUSTOM` (чтение, `NOT_EQUAL 1`, без теста глубины); работает и в WebGL2.
- **Нет в Compatibility:** volumetric fog, SSR/SSAO/SSIL, декали, VoxelGI/SDFGI, TAA/FXAA/SMAA, DoF, GPU-частицы с trails и SDF-коллизиями, compute. Замены: телеграф-круги и маркер посадки — квад-меш, облегающий рельеф; частицы — `CPUParticles3D`; тени — одна `DirectionalLight3D`, в вебе по настройке; glow — только на десктопе.
- **Компиляция шейдеров** в Compatibility происходит при первом показе (программа на шейдер × проход × набор флагов) — в браузере на Windows (WebGL → ANGLE → Direct3D) это сотни миллисекунд на программу, первый червь вешал игру на ~2 с; на ПК программы кэшируются на диске, и этого не видно. Что учитывать:
  - Вариант зависит от того, задевает ли объект **точечный свет** (маячок, молния, знак удара, пламя капсулы, вспышка троеглазки) и прожектор. Поэтому в каждом мире точечный свет есть всегда: фонарь машины (`GameFlow`, `LAMP_*`: отдельный узел у машины, радиус 48 тайлов — весь кадр, яркость 0,001 — днём не видно; ночь, если будет, — та же лампа ярче), невидимая лампа трюма и портрета. Каждому материалу — один вариант «с точечным светом», а не два; `Warmup` снимает образцы только под своим светом на весь кадр. Лимит света на объект в Godot — отдельно по типам (2 точечных, 2 прожектора), лишние отбрасываются по «расстояние / (радиус × яркость)» — почти нулевая лампа уступает настоящему огню первой, у объектов он не пропадает.
  - Шейдер `StandardMaterial3D` живёт, пока жив хоть один материал с тем же набором свойств: образцы прогрева удаляются, поэтому их материалы держит `ShaderCache`. Иначе всё, что появляется и исчезает (молния, смерч, червь), компилировалось бы при каждом появлении.
  - Те же материалы под другим набором источников света — другие программы: у трюма свои прожекторы, поэтому `HangarScreen` под экраном загрузки перебирает сочетания (`_warm_lights`: все прожекторы, все погашены, обычный свет; зарево шахты — точечное, при лампе варианта не меняет). Новый тип света или новое сочетание в трюме — добавить шаг прогрева.
  - **Веб.** Программы WebGL компилируются и линкуются синхронно в главном потоке (Godot сразу проверяет линковку), дискового кэша шейдеров Godot в браузере нет; в Chrome на Windows GLSL идёт через ANGLE в HLSL и компилятор FXC — сотни миллисекунд на программу. Кэш программ браузера ускоряет повторный визит (5 с против 20 с). Меры:
    - правка движка `tools/web/godot_patches/0001-gles3-web-lazy-default-specializations.patch` (§12): штатный Godot при создании шейдера компилирует «программы по умолчанию» — по 4 варианта (цвет, инстансинг, глубина) со всеми типами света, а рисуются они редко; замер: 191 из 309 программ так и не нарисовались и заняли 85 % загрузки. С правкой — только то, что рисуется;
    - лимиты света для веба (`project.godot`): `rendering/limits/opengl/max_lights_per_object.web = 2`, `max_renderable_lights.web = 8` — цикл света в каждой программе короче;
    - правка движка `0002-gles3-web-async-scene-shader-compile.patch`: программы шейдеров сцены собираются без ожидания (`KHR_parallel_shader_compile`; без расширения — как раньше): `ShaderGLES3::_compile_specialization_begin` только заказывает компиляцию и линковку, `_version_bind_shader` возвращает false — объект в этом кадре пропускается (`_render_list_template` так и делает), пока `GL_COMPLETION_STATUS_KHR` не скажет «готово»; тогда `_compile_specialization_finish` проверяет статус, печатает ошибки и берёт расположения uniform. Браузер строит программы в фоне (часто на нескольких потоках), а главный поток в это время собирает мир и синтезирует звуки;
    - всё компилируется под экраном загрузки (прогрев, трюм), после него — ни одной программы. Сколько программ браузер ещё строит, считает оболочка страницы (`window.explorerShaders.pending()`, `ShaderCache.pending_programs()`); прогрев держит образец, а экран загрузки — себя, пока счёт не пробудет нулём несколько кадров подряд: следующие проходы объекта (свет солнца с тенью) Godot заказывает, только когда первый готов.
  - Замер (headless Chrome, AMD iGPU, холодный профиль, `web_bench.mjs`): до мер — 309 программ, 55,6 с главный поток стоял на компиляции, трюм рвался ~60 с; после — 105 программ (156 до постоянной лампы); с фоновой сборкой (правка 0002) главный поток на компиляции не стоит (0,1 с вместо 7,7), экран загрузки уходит через 5,5–6 с после старта страницы (11,4 с без фоновой сборки; без скачивания; на машине игрока — примерно вдвое-втрое дольше), после него — ни одного кадра дольше 50 мс (трюм, выбор машины, «Высадка», десант, 120 с игры; все существа, землетрясение, смерч, водоворот, молния и гроза, кислотный туман, пылевая буря, туман; гибель машины, экран итога с портретом, «Заново» — загрузка 1,1 с без компиляций); поздних программ — не больше одной на прогон, до 15 мс (меньше кадра). Повторный визит — 5 с. Тени солнца стоят ~3 % — оставлены.
  - Новый объект с новыми материалами — добавить его образец в `Warmup`. Проверка: `--shader-audit` печатает материалы с ключом шейдера, впервые появившимся после прогрева; на ПК пики компиляции видны только без дискового кэша — копия проекта с `override.cfg` (`rendering/shader_compiler/shader_cache/enabled=false`, другое `application/config/name`) и `--rendering-driver opengl3_angle`, кадры — по `--log-slow`.
- **Погода в шейдерах:** глобальные `vis_center`, `vis_color`, `weather_center` / `_radius` / `_clear` / `_gas_y` / `_max` / `_gloom`, `storm_center` / `_radius` / `_dark` (объявлены в `[shader_globals]`; необъявленный параметр — ошибка в консоли). `vis_hidden()` и `weather_grade()` — в `visibility.gdshaderinc`, их вызывают шейдеры рельефа, воды, деревьев и находок.

## 11. Тестирование

- `tests/run_tests.gd` (`extends SceneTree`) в `_initialize()` (тесты — после первого кадра) обходит `res://tests/unit/`, загружает `test_*.gd`, вызывает у каждого экземпляра методы с префиксом `test_`, печатает сводку и завершается с кодом 0 или 1. Фильтр — `-- --filter=<подстрока>`.
- `tests/test_case.gd` — базовый класс с `assert_eq`, `assert_true`, `assert_near` (NaN не проходит), `fail`; ошибки копятся в массив. Встроенный `assert` не подходит: работает только в debug и прерывает выполнение.
- Раннер подключает `Logger` (`OS.add_logger`): любая SCRIPT ERROR или ERROR во время теста — падение, даже если проверки успели пройти (ожидаемую ошибку тест объявляет `expect_error`); тест без проверок — тоже падение.
- Запуск — `tools/scripts/test.ps1` или напрямую:

```powershell
$g = ".\tools\godot\Godot_v4.7.2-stable_win64_console.exe"
& $g --headless --path . --import
& $g --headless --path . --script res://tests/run_tests.gd
```

**Ключевые тесты** (всего 40 файлов в `tests/unit/`):

| Тест | Что проверяет |

| `test_terrain_generator::test_determinism` | Один seed и координаты → байт-в-байт одинаковые `ChunkData`; другой seed → отличаются |

## 13. Подводные камни (найдены в M0)

- **Имя enum, совпадающее со встроенным классом** (`enum Material` в `ChunkData`), ломает разрешение типа `ChunkData.Material` — компиляция зависимых скриптов падает. Поэтому enum называется `Mat`.
- **Новый `class_name`** виден другим скриптам только после `--import`: Godot обновляет кэш глобальных классов при импорте. `test.ps1` делает импорт сам.
- **Headless-импорт иногда падает** с access violation (0xC0000005) сразу после правки скриптов или шейдеров; повторный запуск проходит. `test.ps1` делает до трёх попыток.
- **`--script` с ошибкой не завершается**: если `_initialize()` упал до `quit()`, процесс висит вечно. Ручные запуски — с таймаутом.
- **Типизация `:=`** не выводит тип из нетипизированного массива или выражения с `is` — нужен явный тип (`var pressed: bool = …`).
- **Windows PowerShell 5.1** читает `.ps1` без BOM в ANSI-кодировке — скрипты сохраняются в UTF-8 с BOM. Stderr нативной программы при `$ErrorActionPreference = "Stop"` превращается в прерывающую ошибку — в скриптах запуска Godot стоит `Continue`.
- **Веб: `localhost` против `127.0.0.1`.** Браузер может пойти по IPv6 (::1), а Python-сервер слушает только IPv4 — открывать `http://127.0.0.1:…`. Старый процесс на том же порту (Windows разрешает повторный bind) молча перехватывает запросы.
- **Веб-аудио** без жеста пользователя не стартует (`AudioContext was not allowed to start`); в бенчмарке без стартового экрана это ожидаемо.
- **Цикл ссылок `RefCounted`** (запись чанка ↔ её задача) не освобождается сам — ссылку на задачу обнуляем при выгрузке.

## 14. Риски

| Риск | Мера |
|---|---|
| Мешинг в wasm в 2–3 раза медленнее | Секции 16×16, возобновляемые задачи, предвыделенные packed-массивы, нормали в шейдере, никаких временных `Dictionary`/`Vector3` в горячих циклах; при нехватке — секции 8×32 |
| Рывки при стриминге | Гистерезис загрузки и выгрузки, приоритет по расстоянию и предсказанию, пул `ChunkNode` |
| Аллокации и сборка мусора | Пулы узлов и буферов, переиспользование `ArrayMesh`, запись `MultiMesh.buffer` целиком |
| Stencil экспериментальный | Проверен в WebGL2; запасной путь — проход с `depth_test_inverted` |
| Точность float вдали от нуля | За 10 минут ховер уезжает на ~4,5 км — приемлемо; целочисленные координаты в `Grid` оставляют возможность origin shift |
| Веб-аудио требует жеста | Стартовый экран «нажмите, чтобы начать»; геймпад в браузере активируется после первой кнопки |
| Детерминизм между платформами | Битовая идентичность ПК ↔ веб не гарантируется; тесты детерминизма — внутри одной платформы |
| Компиляция шейдеров в кадре | Прогрев материалов и света трюма под экраном загрузки; в вебе — правка движка (без программ по умолчанию) и лимиты света (§10); проверка — `web_bench.mjs --assert` |
